# Design decisions

Where the build specification left room, these are the choices made, with the reason for each.

## Stack and architecture

1. **egui 0.36, egui_dock 0.21, egui_plot 0.37.** The newest egui_dock (0.21) depends on egui 0.36, so eframe/egui are pinned to 0.36 and egui_plot to 0.37, the release built for egui 0.36. Mixing egui versions does not compile.
2. **Threads and crossbeam, no tokio.** One I/O thread per connection and blocking transports with a 5 ms read timeout are simple, deterministic and fast enough (the 5 kHz loopback test shows no backlog). Sends go through a command channel to the same thread, so the UI never blocks on I/O.
3. **Telemetry extraction runs on the I/O thread**, writing straight into per-channel ring buffers behind short-held `parking_lot::RwLock`s. Samples therefore cannot back up or be dropped. UI event queues (decoded messages, raw bytes, text) are bounded per subscriber (200,000 events); an overflow drops events and counts them as *dropped events*. That counter stands in for the spec's "dropped samples".
4. **Own COBS implementation** instead of the `cobs` crate, so the framer works incrementally on the session's buffers. It has unit tests with the reference vectors, and the firmware snippets use the `cobs` crate, which is compatible.
5. **Serial without libudev.** `serialport` is built without its `libudev` feature so the workspace builds without system libraries; on Linux, USB vendor/product IDs are read from sysfs instead.
6. **The `sim` transport is injected.** `pb-core` cannot depend on `pb-sim`, so connectors take an optional simulator factory that the CLI and GUI pass in.
7. **Clock injection.** `pb-core` uses a `Clock` trait. Correlation, device time and the simulator take explicit timestamps and are tested with a manual clock. The sequence runner measures waits with real time because it runs against a real session.

## Configuration

8. **Extra keys** beyond the spec's example, all optional with defaults: `connection.profiles.reset_line`, `reset_pulse_ms`, `bind`, `target` (UDP), `file`/`speed` (replay); `fields.min`/`max` (alarm limits, besides `warn_min`/`warn_max`); `derived.format`; `telemetry.trigger`/`samples` (triggered mode); `simulator.garbage_rate`, `log_interval_ms`, `seed`; sequence-level `non_interactive` and `continue_on_failure`.
9. **Migration.** A file without `config_version` is version 0. The only v0 differences defined are `framing.kind` → `framing.type` and `connection.default` → `connection.profile`. The point is the mechanism: older files keep opening.
10. **Unknown keys** in `project.toml` are warnings, as specified. **Sequence files are strict** (unknown keys are errors), because a typo in a test step should stop the test, not be silently ignored.
11. **Payload `bytes`** accept base64 (Protobuf JSON mapping), arrays of integers, or `"hex:…"` strings, because TOML has no bytes type.
12. **Prompt values** are parsed as TOML values; text that is not valid TOML is sent as a string, so typing `hello` works without quotes.

## Wire format

13. **Length prefixes count the CRC**: `length = len(payload) + len(crc)`, i.e. everything after the length field. This is the common convention for "length of what follows".
14. **Two-byte message IDs are little-endian**, like most small MCUs.
15. **Text passthrough.** A line is the bytes before `\n` that start with 0x21–0x7E and contain only printable ASCII, tab or CR. For length-prefixed framing, lines are recognised only with a sync word, because without one a length byte cannot be told apart from text. For COBS and SLIP, lines may sit between frames, but any run of non-delimiter bytes is also a valid frame prefix (a COBS code byte is often printable and protobuf's most common first byte, tag `0x0A`, is `\n`), so the framer cannot decide at the newline. It holds the lines as a *text chain* at the start of the buffer and decides later: at the next delimiter the whole buffer is first tried as one frame, and a frame that passes the CRC wins; otherwise the chain is emitted as text, cut at the first line boundary that leaves a good frame. When a read times out with nothing received (5 ms of silence), the chain is emitted up to its last non-blank line. Without a CRC this is a heuristic: a chain containing a line of two or more characters is preferred when the rest is a valid frame on its own. Use a CRC when text and frames share a link.
16. **Resynchronisation.** Delimited framers lose at most the frame that garbage ran into. Length framers drop one byte and search again after a bad length or CRC, and report one error per episode, not one per byte.
17. **Simulator corruption** flips one bit of a framed frame, never the trailing delimiter and never into a delimiter value, so a corrupted frame shows up as a CRC error (or a COBS framing error if the code byte was hit) and does not merge with the next frame. Garbage bursts are 1–8 random bytes.

## Codec and correlation

18. **Field paths in id_prefix/fixed modes** may start with the message's own name (`telemetry.vout_raw` against `demo.Telemetry`); that segment is skipped. This keeps channel names the same across dispatch modes.
19. **A repeated field without an index** selects all elements, the same as `[*]`.
20. **Presence.** Unset oneof members and unset message fields produce no channel samples; unset proto3 scalars produce their default (0), as the wire format cannot tell them apart.
21. **Sequence IDs** start at 1, skip 0 (0 marks unsolicited messages), and wrap at 2³¹−1 so they fit `int32` fields. Retries resend the same bytes with the same ID.
22. **A reply with the right ID but the wrong type** resolves the request as an error ("expected `pong`, got `ack`") instead of waiting for the timeout.
23. **Without `response_field`**, or for request types that have no sequence field, the oldest outstanding request expecting the received type takes the reply.
24. **Poll telemetry** requests use no retries; the next poll comes soon anyway.

## Telemetry

25. **Channel values are stored in engineering units** (after `[[fields]]` scale and offset). Enum and bool channels are not scaled.
26. **Derived expressions see raw field values** from the current message first, so `telemetry.vout_raw * 0.0503 * …` in the demo works as written. Then field paths in the message, then the latest channel values. A derived channel updates only when one of its inputs is in the current message.
27. **Device timestamps** are anchored to the host time of the first sample and keep the device's spacing afterwards. Channels from device- and host-timestamped messages then share one time axis. A backwards jump of more than one second re-anchors (device reset).
28. **Statistics** (`std`) are population standard deviation. The live `rate_hz` is (count − 1) / time span. In a sequence capture, `rate_hz` is count / capture duration.
29. **Min/max decimation** keeps one point outside each edge of the view so lines reach the borders.

## Recording and export

30. **Session records** hold codec bytes (framing and CRC removed) for `rx_frame` and `tx_frame`, not raw transport chunks. This makes recordings independent of the framing, lets `decode` work from the embedded schema alone, and lets replay re-frame them with the current project's framing.
31. **Replay** plays received frames and text lines with their original spacing divided by `speed`; sent frames are not replayed, and writes to a replay are dropped.
32. **MCAP topics** are `/rx/<member>` and `/tx/<member>` in envelope mode (one channel per message type, the payload being the member message), `/rx/<Type>` otherwise; text lines and markers go to `/text` and `/markers` with JSON encoding. Log time is the recording's start time plus the host offset, so viewers show wall-clock time.
33. **CSV time** is in seconds on the session clock (device-anchored where configured).

## Sequences

34. **A failing step skips the rest** by default (they are reported as skipped), as a bring-up test usually makes no sense after a failure. `continue_on_failure = true` changes that.
35. **Loops are not test cases**; each executed inner step is, numbered `7.2.1` (loop at step 7, iteration 2, inner step 1). The spec's smoke sequence therefore reports 10 steps.
36. **`within`** is an absolute tolerance used together with `eq`.
37. **Exit code 2** for `run` covers project errors, unknown profiles, failed connections, and steps that error with "not connected"; assertion failures and timeouts give 1.
38. **The demo's `smoke.toml`** sets `non_interactive = "continue"`, so the specified command `protobench run … --sequence smoke --profile sim` passes without flags while other sequences default to `fail`.

## GUI

39. **Two Y axes.** egui_plot has one transform per plot, so Y2 traces are linearly mapped into the Y1 range and the right axis labels show Y2 values.
40. **Two layout files.** The spec saves the layout per project in `layout.json`, but auto-saving into that file meant that trying out a project (the demo, a project in a firmware repo) changed tracked files. Changes are therefore auto-saved to a git-ignored `layout.local.json`, which is loaded first; `layout.json` is the shared default, written only by **View ▸ Save layout as project default**. Layouts without panels are skipped so a project never opens blank.
41. **`layout.json`** is the serialized `egui_dock` state. Rectangles of panes that were never drawn are infinite, which JSON cannot represent, so they are written as 0; they are recomputed on the next frame.
42. **The smoke test** renders real frames without a display through `egui::Context::run_ui`, driving the same `AppState` actions the buttons call; `--window` repeats the run in a real window. This covers acceptance criteria 4 and 5 in CI environments without a GPU.
43. **Badges of composer sends** are keyed `composer: <message>`, so they do not overwrite the badges of configured buttons.
44. **The project editor** updates `[framing]` keys in place (comments survive) but rewrites the `[[connection.profiles]]` array, writing only non-default keys; comments inside profiles are lost. "Save as button" appends with `toml_edit` and keeps everything else.

## Round 2

45. **`expect` window.** The runner subscribes once for the whole run and buffers received messages (at most 50,000). An `expect` step matches the oldest message of the expected type received since the *previous* step started, so a reply to a fire-and-forget `send` is not missed when it arrives before the `expect` step begins. Each message is consumed once: a reply used by a `send … expect` step, or matched by an earlier `expect`, cannot match again. Messages older than the previous step's start are dropped.
46. **TCP server state.** A `tcp_server` session is `Listening` ("Waiting for client") until a client connects and again after it leaves. Losing the client fails pending requests with "client disconnected" and resets the framer. Sends without a client fail with "no client connected"; periodic sends pause. The CLI waits for a client as long as it takes.
47. **Write timeouts.** Writes block at most 1 s. A TCP client whose peer stops reading for that long has lost the link (part of a frame may have been sent, so the stream cannot continue) and reconnects. A TCP server drops that client and keeps listening. A serial write keeps writing partial chunks until the deadline and then fails only that request; the port stays open. Once a write shows the link is gone, queued writes fail at once instead of blocking again.
48. **Capture window for every named channel.** A `capture` step measures every channel it lists and every channel an assertion names over the capture window only.
49. **Repeated fields in assertions.** A path that matches several elements (`adc`, `adc[*]`) passes only if every element passes; the report's `measured` is the array.
50. **Non-finite values** (NaN, ±∞) fail every `eq`, `min` and `max` check, because NaN compares false with any limit and would otherwise pass.
51. **`protobench check`** reports the project's own diagnostics plus semantic checks of every sequence file (commands, message names, assertion and `save` paths against the reply type, channels, statistics, undefined `${vars}`) and the channels named in `layout.json`. Unknown layout channels and undefined variables are warnings (a panel stays empty; a variable may come from a script), everything else is an error. Exit code 1 means at least one error; warnings alone exit 0, so CI fails only on real breakage. A channel is *known* if it matches a configured telemetry path (`[*]` and unindexed repeated fields match any index) or a derived channel.
52. **`decode --range`** uses the same time axis as CSV export (seconds on the session clock, device-anchored where configured). `--channels` names that are not in the recording are an error rather than an empty column.
53. **Scripts use Rhai** (pure Rust, embeddable, sandboxable). The engine has no module resolver and no `eval`, so scripts cannot read files or the network. Limits: 50 million operations, 64 call levels, 1 MiB strings, 100,000-element arrays, 10,000-entry maps, and a wall-clock `timeout_ms` (default 60 s) that also bounds `sleep`. Abort stops a script at the next operation or within 10 ms of a `sleep`.
54. **Script variable access is `get_var(name)`**, not `var(name)` as first planned: `var` is a reserved word in Rhai.
55. **Script outcomes.** A script that throws (`throw`, `fail(msg)`) fails the step; a false `check(cond, msg)` is a failed assertion, so the step fails but the script keeps running; anything else that stops a script (syntax or type errors, a limit, abort) is a step *error*. `send`/`send_msg` never throw: they return `#{status, response, latency_ms, attempts, error}`, so a script decides what a timeout means. The script's final value, unless `()`, is stored in the step's `measured.result`.
56. **Script files** (`file = "x.rhai"`) are resolved relative to the sequence file and loaded when the sequence is parsed, so a missing file is a parse error. `protobench check` compiles every script and reports syntax errors with the step's line and the line within the script; `set_var("name", …)` counts as defining `name`.
57. **`SessionHandle`** is a cloneable `'static` handle (send, telemetry, codec, clock) so scripts and other threads can use a session the runner only borrows. It does not keep the I/O thread alive.
58. **Foxglove WebSocket server on threads.** `tungstenite` in blocking mode, one accept thread and one thread per client, like the rest of `pb-core` (B4 forbids mixing in an async runtime). A client's outgoing queue holds 20,000 frames; when it is full new frames for that client are dropped and counted, so a slow viewer never slows the session.
59. **Foxglove topics are the MCAP topics** (`/rx/<member>`, `/tx/<member>`, `/text`, `/markers`), produced by one shared module so a live view and an exported file look the same. Every topic the codec can produce is advertised when a client connects; a topic that appears later (e.g. an envelope with no member set) is advertised on the fly. Protobuf channels carry the whole `FileDescriptorSet` (base64) as their schema; `/text` and `/markers` are JSON with a JSON Schema.
60. **Foxglove log time** is Unix time: the session timestamp plus the session clock's wall-clock offset, so Foxglove's timeline shows real time.
61. **The Foxglove server binds `127.0.0.1` by default.** Serving device data to the network is opt-in (`--foxglove-bind 0.0.0.0`, or the bind address in Settings). The GUI's default port is 8765, Foxglove's usual one. In the GUI the toggle follows the connection: the server starts with each session and stops on disconnect.
62. **The subprotocol is selected when offered.** A client that does not offer `foxglove.websocket.v1` is still served (the reply then has no `Sec-WebSocket-Protocol`), which helps debugging with generic WebSocket tools.
63. **Parquet layout = joined CSV.** `time_s` (non-null `float64`) plus one nullable `float64` column per channel, as-of joined on the union of timestamps by the same code as the joined CSV, so both exports always have the same rows. Column names are the channel names. Snappy compression; rows are handed to the writer in batches of 65,536.
64. **Parquet is a default-on cargo feature** (`pb-core/parquet`) because `parquet`/`arrow` add about 40 s to a clean build. Without it, `export_parquet` still exists and returns "this build has no Parquet support", so the CLI and GUI need no conditional code.

## Round 4

65. **`port = "auto"` needs exactly one match.** Round 1 opened the first port matching `usb_vid`/`usb_pid`, so with two identical boards attached the choice depended on enumeration order and could change between reconnects. Now several matches are an error that lists each port with its USB serial number and says to set `usb_serial` (or to name the port, when the boards report no serial number). Without any filter, `auto` takes the only USB serial port, ignoring legacy ports such as `/dev/ttyS0`, and falls back to the only port when none is USB.
66. **CI pins Rust 1.95.0**, the version the acceptance criteria name, so a new stable release with new clippy lints cannot turn a green branch red overnight. Moving to a newer toolchain is a deliberate one-line change.
67. **Links say how they deliver data.** `Transport::message_based()` is true when every read is one whole message (UDP, and the MQTT and CAN links), and `TransportKind::link_kind()` gives the same answer from the config (stream, message or either), so `check` can warn about a framing that cannot work (`none` on a byte stream, a framer on a message link) before anything connects. UDP, the simulator and replay are "either": a datagram can carry COBS frames, and the simulator's loopback and replay keep one frame per read when the framing is `none`. The simulator then writes each frame separately instead of one buffer per step.
68. **Side-channel text** (`Transport::take_text()`) is how a link hands over text that does not travel in the byte stream: RTT's printf channel, and replayed text lines. The session treats those lines exactly like text passthrough (console, counter, recording). Replay used to push text back into the byte stream with a newline, which only worked when text passthrough was on.
69. **Each extra device is its own project**, referenced from `[[devices]]`, rather than a section inside one `project.toml`. A device brings its schema, framing, codec, correlation, commands, telemetry, field overlay and simulator; inlining all of that would duplicate the device's config in every bench project and drift from the device's own repository. Referencing keeps one `project.toml` per firmware and lets the same device project be used alone.
70. **`main` keeps plain channel names; other devices get `<device>.`.** Prefixing everything would have broken every existing layout, sequence and derived expression; prefixing the others costs nothing because they are new. `check` warns when a `main` channel starts with a device's name, the only case where names could collide. Dots were already allowed in channel names and expression variables (field paths), so no escaping is needed.
71. **Devices nest one level.** A bench of benches has no use case worth the cycles and diamond cases it brings. The exception is a device that is the project's own folder (two identical boards), whose `[[devices]]` are ignored.
72. **One session per device, one shared clock and telemetry store.** Sessions stay independent (a device that drops does not stall the others), while the shared clock puts every sample on one time axis and the shared store makes cross-device plots, captures, derived channels and exports work with no new code paths. Derived channels of the main project are evaluated on `main`'s messages with an as-of read of other devices' newest values, the same rule the joined CSV uses.
73. **Recording format version 2** (`PBSESS02`): the header lists every device with its project text, one descriptor set per device follows, and each record carries a device byte. Version-1 files from rounds 1–3 still open, as device `main`; a committed round-3 recording is the test fixture. New recordings are always version 2, so older builds cannot read them (they say so: an unknown `PBSESS` version is reported as written by a newer ProtoBench). Several sessions share one writer through a sink per device; finishing one device's sink only flushes, so a device can disconnect while the others keep recording.
74. **A run checks its devices first.** Steps that name a missing or disconnected device would otherwise fail one by one with confusing messages, possibly after an operator prompt. The run instead stops with a single `devices` error before anything is sent, and the CLI exits with 2 (connection error). Steps that name no device keep the old behaviour, so single-device sequences are unaffected.
75. **The MQTT client is written in-house.** The maintained Rust clients (rumqttc, paho's Rust bindings) are built on tokio or a C library, and B4 keeps `pb-core` on plain threads. MQTT 3.1.1 with QoS 0/1 is about ten packet types; the client is a few hundred lines on a blocking socket with the same read and write timeouts as the other links, and a small broker in `pb-sim` reuses the packet code for tests. TLS is rustls with the `ring` provider (no cmake or nasm to build) and the OS root store.
76. **QoS 2 is left out.** Exactly-once needs a four-packet handshake and persistent state on both sides for each message, and a test bench gains nothing from it: the sequence-ID field already lets firmware drop a duplicate command, and duplicated telemetry is harmless. QoS 1 gives at-least-once: a persistent session while the link is down, and an outbox that survives reconnects (kept by the connector, not the connection) so unacknowledged commands are sent again with the DUP flag.
77. **One MQTT message is one frame.** MQTT already delimits messages, so `framing.type = "none"` is the expected setting; `check` warns about a framer on a message link. Text on a separate topic is not supported in this round.
78. **CAN goes through slcan first.** An slcan adapter is a serial port with an ASCII protocol, so it works the same on Windows, Linux and macOS with the serial code ProtoBench already has, costs little, and is testable here: the tests put the simulator behind an emulated adapter on a loopback (and, by hand, a socat pseudo-terminal pair). SocketCAN covers Linux adapters with kernel drivers (PEAK, Kvaser, gs_usb); its test is ignored by default because it needs a `vcan0` interface, and the WSL2 kernel this was built on has no `vcan` module. PCAN-Basic and Kvaser CANlib (vendor DLLs) remain later work.
79. **ISO-TP is ProtoBench's own**, a state machine shared by both directions and driven by the transport, rather than the Linux kernel's `CAN_ISOTP` sockets: it has to work over slcan and on every OS. The sender blocks in `write_all` while it waits for flow control (bounded by N_Bs) and handles frames that arrive meanwhile, so a device that streams while the host sends a long command is fine. A property test sends random messages of 0–4095 bytes both ways over classic CAN and CAN FD with random block sizes, STmin and padding; it found an overflow in the block counter on its first run.
80. **A refused write is not a lost link.** `InvalidInput` and `InvalidData` from a transport (a message too long for one frame, an ISO-TP overflow from the device) now fail only that request, like a timeout, instead of reconnecting.
81. **RTT goes through probe-rs**, not J-Link's telnet port: probe-rs drives J-Link, ST-Link and CMSIS-DAP probes directly, on every OS, with no vendor software running, and finds the control block itself (by the ELF symbol or by scanning RAM). The telnet route still works through a `tcp_client` profile and is documented for people who already run a GDB server. probe-rs is built without its CMSIS-DAP v1 (HID) support, which needs hidapi and libudev headers; CMSIS-DAP v2 probes, J-Link and ST-Link do not.
82. **probe-rs is a cargo feature** (`rtt`), off in `pb-core` and on by default in the CLI and GUI. It is the largest dependency in the tree; the library and its tests build without it. The transport sits behind a small `RttTarget` trait (read an up channel, write a down channel), so routing, text lines, full down buffers and reconnects are tested with a mock; real probes are on the bench checklist.
83. **RTT text has its own channel.** A second up channel (`rtt_text_channel`) goes to the text console through `take_text`, so a firmware's `printf` and its protobuf stream no longer share one byte stream and text passthrough is not needed. The CLI and GUI quiet probe-rs's own log below errors by default (it warns about every probe driver on machines without a USB bus).
